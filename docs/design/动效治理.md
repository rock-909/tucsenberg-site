# 动效治理

## 何时允许动效

动效只能解释状态、层级或导航路径。优先 CSS、现有 state 属性和浏览器能力；不要为了“高级感”增加页面级 reveal、长 duration 或新 motion 依赖。

## Server/Client 边界

静态营销内容保持服务端渲染。不要为了动画把整个 section 或页面改成 Client Component。首屏 claim 默认可见，动效失败时内容仍完整可读。

## 无障碍与性能

必须尊重 prefers-reduced-motion，并避免影响键盘焦点、读屏顺序、布局稳定性和 LCP。动画涉及 transform、height、opacity 或加载状态时，先证明它不会制造 CLS 或隐藏正文。

## 验证

动效变更至少检查无 JS、reduced-motion、窄屏、键盘和真实页面截图/浏览器行为。没有独立 proof 时，不扩大动效范围。
