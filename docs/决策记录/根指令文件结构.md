# 根指令文件结构（AGENTS.md / CLAUDE.md）

**裁决日期**：2026-07-24
**状态**：现行
**推翻**：2026-07-11「双文件同步维持」裁决（记录于 `docs/技术难题/门禁机械遵守审查2026-07/根指令文件精简执行文档.md` 第 108-112 行，该文档为历史存档，不修改）

## 裁决

1. `AGENTS.md` 是唯一正本，自包含。
2. `CLAUDE.md` 只有一行 `@AGENTS.md`。
3. 这两个文件不接受任何机器强制的内容断言。

## 为什么推翻 2026-07-11 的裁决

2026-07-11 评估过 Next.js 官方 AI agents 指南推荐的「CLAUDE.md 只写 `@AGENTS.md`」写法，业主否决，记录的唯一理由是：

> 需连带改 website-config-runtime-boundary 与 component-governance 两个测试的断言方式

2026-07-24 业主判定这些断言本身就是错误的把关方式——它们把 `ls` 的输出和文档散文钉成必过断言，逼两个文件逐字保持一致，属于 `判断准则` 定义的「固化环」。当初的阻碍被判定为需要拆除的对象，否决理由随之失效。

## 为什么 AGENTS.md 必须自包含

`@path` 导入是 Claude Code 独有语法。Cursor、Copilot 等读 `AGENTS.md` 的工具不会展开它，只会看到字面文本。因此共享只能单向：`AGENTS.md`（全文）→ `CLAUDE.md`（导入）。

## 为什么没有规则路由表

曾经两个文件各有一份「任务类型 → 该读哪个规则文件」的对照表。删除理由：

- Claude Code 通过 `.claude/rules/*.md` 的 `paths:` frontmatter 自动按路径加载，不需要表；
- 其他工具需要的信息，规则文件的文件名加自身 frontmatter 已经表达；
- 表里的跨文档指针在规则文件内部已有原文（例如设计令牌指向 `docs/design/设计真相.md`，见 `.claude/rules/ui.md`）。

表存在的唯一效果是复述规则文件已说过的话，并制造两个根文件之间的分叉。

## 为什么 `.claude/rules/ui.md` 不再列设计文档清单

`ui.md` 曾经列两份「改品牌色前读这 4 份 / 改区块结构前读这 3 份」的清单，共 7 个指针。删除理由：

- 清单本身会过期。2026-07-16 的方向 E 视觉裁决落在 `docs/决策记录/`，7 份文档没有一份提到它，按清单走会读到已被取代的基线；
- `docs/design/设计真相.md` 的「真相来源」一节已经是设计文档的枢纽，清单是第二份枢纽；
- 规则文件是工程边界的家（组件复用顺序、客户端岛边界、Cloudflare 图片基线、Tailwind v4 事实），设计表达的家在 `docs/design/` 与 `docs/决策记录/`。两者混在一起，视觉方向每变一次就要改规则文件。

现在 `ui.md` 只保留一个指针，指向 `docs/design/设计真相.md`；该文件顶部新增「当前阶段」一节，声明设计探索期并指名现行视觉裁决。新裁决产生时只改这一处。

## 约束

新增守卫不得要求 `AGENTS.md` 或 `CLAUDE.md` 包含特定语句。要守的是这些语句描述的行为，守在行为发生的地方。该约束已写入 `AGENTS.md` 的 `判断准则` 一节。
