# 技术问题与决策

这里只保留仍影响当前行为、上线判断或未来迁移的事项。每项记录现状、影响、当前处置、重新评估条件和真相入口。

## 当前约束

- pnpm build、pnpm website:build:cf 和 Playwright webServer 可能共同写 .next，必须串行；
- Cloudflare/OpenNext、PPR/cacheComponents 和 middleware/proxy 迁移有明确当前边界，变更前先做官方语义和运行 proof；
- PDF 和静态资源 header 必须按实际发布路径和 Wrangler 语义证明；
- client-boundary budget 是机器消费的质量基线，不是人工文档；
- public launch proof 必须区分 release、部署、真实询盘和 owner receipt；
- 方向 E 的视觉裁决仍有未完成落地约束；
- 产品文案归属冲突必须以当前产品事实和 owner 决策解决，不从旧审查报告复制结论。

## 演进候选

### 未来语言扩展

当前 English-only；若增加语言，先更新 locale 配置、messages、MDX、SEO 和路由测试，不复制现有页面作为临时方案。

### CMS

只有当 Git-backed content-as-code 编辑成本成为真实瓶颈时，才评估薄 CMS 层。CMS 不能先替换产品事实和审核后的 MDX。

### 平台或构建迁移

只有在 Next/OpenNext/Cloudflare 支持、构建时间、运行成本或平台生命周期触发时重新评估。迁移必须先做 parity、部署和真实业务 proof。

## 长期决策

- Content-as-code：页面正文、messages 和产品事实继续由 Git 管理；CMS 若出现，只能先做 Git-backed 编辑层，保留审核、版本、回滚和部署真相。
- English-only public surface：当前不暴露 locale 前缀和语言切换，i18n 管道保留到真实多语言需求出现。
- 单一询盘写入口：表单、验证、产品上下文和 provider handoff 保持一条真实链路，避免 owner 追踪和错误处理分裂。
- Server-first UI：默认使用 Server Components，只有真实交互才进入 Client，以保护首屏、SEO、无 JS 可读性和客户端边界预算。
- Cloudflare/OpenNext proof 分层：普通 build、Cloudflare build、Wrangler dry-run、部署 smoke 和真实服务 receipt 分开判断，不能相互替代。

业务范围、真实性能瓶颈、平台生命周期、provider 约束或多语言需求发生变化时，重新评估对应决策。
