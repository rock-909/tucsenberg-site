## 待确认问题

### Airtable 超时后的晚到请求

现状：询盘链路给 Airtable 8 秒等待预算；超时只会停止当前请求继续等待，底层 SDK 的重试不一定被取消。

影响：系统可能先记录失败，稍后 Airtable 又落下一条记录；买家重试时可能形成重复线索。

当前处置：先保持现有简单链路，不增加取消和幂等框架。前端继续缩短等待时间不能解决底层晚到问题。

重新评估条件：运行中出现晚到或重复记录，再评估 AbortSignal，或稳定 submission ID 配合 provider 幂等。
