# 带扩展名的不存在地址返回 500 而非 404

**发现时间**: 2026-07-25（整改 Wave 5 移除废弃图片后的预览验证）
**状态**: 已确认，未修复
**影响面**: 所有不存在的、路径里带点的地址

## 现象

生产构建下访问任何不存在的带扩展名地址，返回的是 `500 Internal Server Error`，
而不是应有的 `404 Not Found`：

```
/random.txt              → 500
/does-not-exist.svg      → 500
/next.svg                → 500   （Wave 5 移除后）
/nope                    → 404   （不带点的地址正常）
```

Wave 5 移除的五张废弃图片里，`/images/*` 四个走 `public/` 静态目录仍返回 404，
只有根目录的 `/next.svg` 落进这个坑。

## 为什么会这样

这是主干上早就存在的问题，不是 Wave 5 引入的（在 `a1af99b` 上同样复现）。

两个条件叠加：

1. `src/middleware.ts` 的 matcher 是 `/((?!api|_next|.*\..*).*)`，
   **带点的路径被排除在中间件之外**，拿不到 locale 路由改写。
2. 站点没有根级 404 页。唯一的 404 页在 `src/app/[locale]/not-found.tsx`，
   它必须有 locale 段才能渲染。

于是带点的地址既进不了 locale 路由，又没有根级兜底页，Next 只能抛错，
最终变成 500。

## 业务影响

- 搜索引擎把 5xx 当作"站点故障"，比 404 更容易触发降权或暂时移出索引。
- 买家点到过期的资料链接，看到的是"服务器错误"而不是"页面不存在"，
  读起来像整个站挂了。

## 为什么 Wave 5 不修

修法需要 Next.js 的 `global-not-found` 约定：本站的根布局是
`src/app/[locale]/layout.tsx`（顶层动态段），官方文档明确说这种结构无法用
普通的根级 `not-found.tsx` 组合出全局 404，只能用 `global-not-found.tsx`。
而它需要：

- 打开 `next.config` 里的 `experimental.globalNotFound` 实验开关；
- 写一个自带 `<html>`/`<body>`、自行引入样式和字体的完整文档页；
- 决定这个页面用哪套文案（站点目前只有 en，但它在 locale 之外）。

实验性 Next 开关按 `.claude/rules/cloudflare.md` 需要单独的 Cloudflare/OpenNext
运行时验证通道，属于路由行为改动，不是"删除死资产"这波的范围。

## 修复时要做的事

1. 打开 `experimental.globalNotFound`，新增 `src/app/global-not-found.tsx`。
2. 复用 `LocalizedNotFoundView` 的文案来源，避免两套 404 文案漂移。
3. 补一条路由契约测试：不存在的带点地址必须返回 404。
4. 按 Cloudflare 规则跑 `pnpm build` + `pnpm website:build:cf` + 预览冒烟，
   确认 Workers 运行时行为一致。
5. 更新 `docs/项目基础/行为合约.md` 里的 404 行为描述。
