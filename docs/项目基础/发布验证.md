# Release Proof

Use this for Tier A or production-sensitive changes.

## Command

```bash
pnpm release:verify
```

It runs the canonical release sequence through `node scripts/starter-checks.js release-verify`.
The authored source of truth for that sequence is `scripts/quality/release-proof-manifest.js`.
The visible command block below is checked against the manifest so the runbook,
runner, and tests do not drift.

Local release proof is not public launch proof. Public launch still needs `PUBLIC_LAUNCH_STRICT=true node scripts/starter-checks.js validate-production-config`, deployed lead canary, and manual launch gate.

Pull request CI does not prove the Cloudflare Free gzip budget, because the
Wrangler dry-run needs Cloudflare credentials and is skipped for
`pull_request`. Before merging a Cloudflare-size-sensitive PR, record either a
`workflow_dispatch` CI run or a local `pnpm release:verify` run against the
exact head SHA.

Lighthouse remains manual performance proof. It is not part of default CI, git
hooks, or `pnpm release:verify`; run `pnpm website:lighthouse` only when a
change makes a page-performance claim. That script runs its own
`APP_ENV=production next build` first, so it always measures a correct,
current build instead of whatever `.next` happens to be lying around.

## Rules

- Run build before `website:build:cf`; never run them in parallel.
- `cf-static-asset-headers` reads `public/_headers` and
  `.open-next/assets/_headers`, works out the URL every published download and
  every published `_next/static` file is actually served from, and applies
  wrangler 4.100.0's own rule semantics to prove what each of those files really
  receives: every download carries `X-Robots-Tag: noindex`, and every
  `_next/static` file carries a one-year immutable `Cache-Control` that no later
  rule overrides and no `Vary: *` makes unreusable. It also sweeps both published
  trees for document files and demands `noindex` on every one of them, wherever
  it sits: a quotation dropped into `public/` instead of `public/downloads/`
  would otherwise go out with no rule covering it at all. What counts as a
  document is the file's extension (`.pdf`, `.docx`, `.xlsx`, `.csv`, `.txt` and
  the like), not the folder it is in; anything whose extension is not on that
  list — images, fonts, JavaScript — carries no crawl policy this check enforces.
  The only files let through by location are the plain-text ones standards
  require crawlers to read: `.txt` under `.well-known/`, plus `/robots.txt` and
  `/ads.txt`. A `.pdf` in any of those places is still demanded to carry
  `noindex`. It does not require any particular
  route to be written — a different spelling that still covers every real file
  passes. It also refuses to pass, rather than guess, when something makes the
  served URL or the served value unknowable: a duplicated route, a host that is
  not one exact literal, a header name or value the runtime rejects, a directory
  whose on-disk name differs from the one in the URL, a `.html` file in either
  protected subtree, an empty protected directory, a directory, entry, or file it
  could not read, a `_redirects` or `.assetsignore` file, a missing or unparsable
  `wrangler.jsonc`, a missing `_headers` on either side, a header value whose
  quotes never close, a second cache lifetime sitting beside the expected one so
  which of the two wins cannot be proven, an `assets` setting it does not model
  set to something other than wrangler's own default (`html_handling`,
  `not_found_handling`, `run_worker_first`), or a `wrangler.jsonc` with no
  `assets.directory`. Separately, it also fails when `wrangler.jsonc` sets an
  `assets` key wrangler itself does not recognise. That one is not a gap in this
  check: wrangler ignores such a key, so the setting is simply not doing
  anything on the live site. It runs on every pull request in `ci.yml` as well as
  in `release:verify`.
- The Wrangler preview dry-run is the source-checkout Cloudflare Workers Free
  runtime budget proof: keep Worker upload below **3000 KiB gzip**, with a
  preferred target below **2700 KiB**.
- This release proof covers the current single catalog site only.
- Release-proof failure means not release-proven.
- Release-proof is technical evidence, not automatic public launch approval.
- Public launch still needs deployed smoke, real service canary, and owner signoff.

## Dirty worktree

dirty worktree rule:

If unrelated dirty files exist, report:

1. targeted proof for changed seam;
2. clean branch proof for whole-repo claims.

Do not collapse them into one “green” claim.

When the change touches single-site truth, name the exact seam: `src/config/single-site.ts`, `src/config/single-site-page-expression.ts`, or `src/config/single-site-seo.ts`.

## Extra launch canary

For public launch:

```bash
POST_DEPLOY_TEST=1 PLAYWRIGHT_BASE_URL="$DEPLOYED_BASE_URL" pnpm exec playwright test tests/e2e/smoke/
```

This proves the deployed path only when the environment uses real deployed credentials and the resulting Airtable/Resend/Turnstile state is checked.

This extra step is a manual launch gate; a GET deployed smoke does not prove Airtable or real lead delivery.
The current Playwright canary verifies the Airtable record (`recordCreated`); `ownerNotified` / owner notification still needs manual target-system confirmation.
